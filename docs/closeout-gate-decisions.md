# Close-out state gate: decisions

Branch `vic/feat/closeout-diff-gate`, from `vic/exp/mixed-stream-smoke` (`dba68a5c`), 2026-10-02. Autonomous; one entry per decision. No cluster experiments were run (Tier 1 holds the cluster budget; Codex quota read 92%).

## Why

The mixed-stream Tier 0 smoke (cold C1 through the full conductor) repaired two of three faults and never found the `deny-all-recommendation` NetworkPolicy. Every health detector was clear, the verify burst passed 5/5, and the official `NetworkPolicyMitigationOracle` failed. The responder's own state-diff report listed the new policy ("Changed since the incident request was taken") and the responder ignored it. Diagnosis: an SDO coverage gap, with a traffic probe that is blind to the fault (probable cause: an established connection survives the policy; unconfirmed). Option 1 from that diagnosis: before closing, do not accept a diff that nobody repaired or explained.

## Decisions

| # | Decision | Alternatives | Why |
| --- | --- | --- | --- |
| 1 | **Owner: the Go controller** (`controller/runtime/closeout_gate.go`, called from `maybeCloseIncident`). | (a) the responder's `sdo incident status` verdict; (b) the Python broker at closure; (c) the SREGym adapter's submission path. | The controller already owns closure, the final diff (`finalStateChangesLocked`), the bounded follow-up chain and persisted attempt counts. (a) is advisory and the responder had already ignored it. (b) acts after the closure is cut, too late to send the incident back. (c) would be benchmark-specific and `controller/runtime` must stay transport-neutral. The gate is deterministic Go with no LLM and no benchmark verdict. |
| 2 | **Rule: a diff object is cleared by a successful repair action whose `resources` list it, or by a responder acknowledgement with a reason; anything else is sent back.** Kind matching is case-insensitive with plurals normalized; all change types (added, modified, removed) count. | Only added/modified (the literal ask); matching by first-observation time. | A removed object nobody restored is the same kind of residue (a deleted ConfigMap). A repair that returns an object to the baseline removes it from the diff, so it never reaches the gate at all; the rule only handles what is still different. First-observation timing is the diagnosis verifier's job and cannot tell "unrelated" from "unrepaired". |
| 3 | **Reuse the bounded follow-up chain** (`MaxFollowUps`, cooldown, persisted attempt) for "send back"; the request carries one controller-authored finding per object (detector `sdo-closeout-gate`, rule `closeout.unrepaired-state-change`) and the diff. `startFollowUpLocked`'s body was split into `openFollowUpLocked` with no behavior change. | A new dispatch path; a new retry counter. | One responder in flight, one closure per chain, one bound. The finding is informational: the follow-up request's validation needs a finding, and closure still waits only on health detectors, so the synthetic finding never enters the finding tracker. |
| 4 | **Bounded, then marked.** With the follow-up budget spent, or `MaxFollowUps = 0`, the incident closes with `closure.closeout_gate = {outcome: exhausted, objects}`. All-acknowledged closes with `outcome: acknowledged` and each reason. | Block closure forever; fall back to detector review. | A gate that can loop is worse than the fault. Closing with a mark keeps the incident flowing and the evidence in the record. |
| 5 | **Responder justification: a new optional `acknowledged_state_changes` result field** (`kind`, `name`, `reason`, reason required) in Go and Python. The Codex output schema and one prompt paragraph add it only when the controller job sets `SDO_CLOSEOUT_STATE_GATE=1` (via `--responder-env`). | Always include it; infer acknowledgement from `confirmed_root_causes`; free-text parsing. | Gate off must leave arguments, schema and prompt byte-identical so existing comparisons stay valid. Acknowledgement has to be explicit and structured to be checked deterministically. The prompt text names no kind (fairness rules). |
| 6 | **An `exhausted` closure is not health-verified in the broker** (`BrokerClosure.health_verified` is false), so no verified outcome and no learning from it. `acknowledged` stays verified. | Leave `health_verified` alone; add a new outcome class. | Learning a playbook from a response that left an unexplained diff is how memory goes wrong (stale/false memory is worse than none). The existing unverified path already does the right thing, and a bounded exhausted close is exactly "not independently verified". |
| 7 | **Opt-in, off by default** (`--closeout-state-gate`, `ControllerInstallConfig.closeout_state_gate`, SREGym `agent_config.sdo_codex.closeout_state_gate`, fastloop `--closeout-state-gate`). | Default on. | It changes closure behavior and cost (possible extra responder runs); matches how every other behavior-changing feature here ships. A confirming rerun decides the default. |
| 8 | **Repaired/acknowledged sets are in controller memory and accumulate across the follow-up chain, not persisted.** | Persist them in the state store. | The attempt counter that bounds the loop is already persisted. A restart mid-incident loses the sets, which can cost one extra bounded follow-up, never an unbounded loop. Persisting means a state-store schema change for a rare case. |
| 9 | **Scope of "any kind" is the tracker's kinds** (Service, Deployment, StatefulSet, DaemonSet, NetworkPolicy, ConfigMap, Secret, Role, RoleBinding); SDO's own `sdo-*` objects are already excluded by the tracker. | Extend the tracked kinds (Pods, ReplicaSets, Ingress, HPA). | These are configuration kinds the baseline diff already covers; pods and ReplicaSets churn on their own and would make the false-positive rate high. Extending coverage is a separate decision. |

## Hazards and how each is handled (tests in `controller_closeout_gate_test.go`)

- **Objects touched by the responder's own repair do not block** (also across the follow-up chain; case-insensitive kind). Failed repair actions do not count.
- **Resources added by the app's own controllers or operators** are outside the tracked kinds (ReplicaSets, Pods, Endpoints are not tracked). A tracked-kind object an operator creates or edits would appear in the diff; the responder acknowledges it with a reason, at the cost of at most one follow-up. That is the accepted false-positive path; the prompt asks for the reason on the first attempt so the follow-up is normally unnecessary.
- **Decoys/noise unchanged since the baseline** never enter the diff (existing filtering), so they cannot trip the gate.
- **Bounded**: exactly one follow-up with budget 1 (`TestCloseoutGateIsBoundedAndMarksExhaustion`), persisted attempt count unchanged.
- **Healthy single-fault incidents**: a correct repair returns the object to the baseline, so the final diff is empty and the gate is silent (`TestCloseoutGateStaysQuietOnAHealthySingleFaultIncident`). A repair that legitimately leaves a persisted difference (for example a source fix that rolls the Deployment) must list the object in `resources`, which the responder prompt already requires ("list every object each action changed").
- **Gate off, or no baseline**: no behavior change.

Not measured: the false-positive rate on real runs. It needs a confirming rerun (below); until then it is an estimate from design, not a measurement.

## Confirming rerun (not run)

A rerun of the cold C1 stage needs, on the `vic/exp/mixed-stream-smoke` branch:

1. Merge this branch (or cherry-pick), then rebuild the controller, responder and validator images under a new private tag (the earlier smoke used `mx1`; `SDO_VALIDATOR_IMAGE` must point at the same build, a stale `v0.1.0` fails the lifecycle's link detector compile).
2. In `benchmarks/sregym/experiments/mixed-stream/tier0_smoke.toml` add `closeout_state_gate = true` next to the all-on keys, keep `max_follow_ups = 3`, and keep the stage and judge unchanged.
3. A private kind cluster with Calico (a new prefix), host load below 20, and a Codex quota reading below 97% (the last reading was 92% and stale).
4. Pass condition: either the NetworkPolicy is repaired (official oracle passes) or the incident closes with `closeout_gate.outcome` set and the receipt marked unverified; and no follow-up fires on a healthy single-fault stage (run one C-free single-fault stage after it to measure the false-positive rate).
5. Budget: about 35 minutes for the C1 stage (the first run took 33 minutes, ~12 of them setup) plus about 20 for the single-fault control; stop on the usual 10-minute stall rule.
